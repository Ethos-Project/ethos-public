## Goal

Define the research, UX, product requirements, and evidence-bounded suggestive-insight model for the S.O.C.R.A.T.E.S. administrative platform.

## Approved ownership split

- **Logos:** research, UX, product definition, interpretive models, and suggestive-insight design.
- **Nomos:** operational authority, workflow governance, schemas, permissions, audit, state transitions, and cross-repository standards.
- **Products:** deployable UI/runtime and Product-owned adapters after separate approval.
- **Cogni-Core:** protected cognition only; never administrative authority or a direct UI dependency.

Nomos governance and authority structures may be used as the reference model for S.O.C.R.A.T.E.S. oversight, management, and administrative workflows. The UI and insight layer may explain or recommend, but cannot mutate authoritative status without an approved Nomos transaction and human gate.

## Required design work

- [ ] Define administrator personas and bounded use cases.
- [ ] Define portfolio, repository, product, dependency, workflow, risk, evidence, and decision views.
- [ ] Define readonly-first behavior and accessible fallback views.
- [ ] Define suggestive insights with source evidence, uncertainty, freshness, and counterevidence.
- [ ] Define prohibited autonomous scheduling, approval, issue closure, merge, deployment, or governance mutation.
- [ ] Define human approval and two-key controls for high-risk actions.
- [ ] Define privacy and access-classification requirements.
- [ ] Define renderer-neutral handoff contracts to Nomos and Products.
- [ ] Reconcile this issue with Logos #15 and Nomos #33 without creating competing canon.
